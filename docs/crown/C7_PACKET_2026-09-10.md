# C7 — the per-module analysis ledger (crown stage 2a)

*Packet written 2026-09-10 by the Opus compiler partner for itself, per the
plan's order. Stage 2a is `PLAN.md`'s own named gate for stage 2c: "you must not
claim savings you have not measured (2a) before building the machinery that banks
them". This packet implements the measuring, not the banking.*

## What stage 2a asks for

> instrument `Zcu` to attribute analysis work (units analyzed, ZIR→AIR lowering,
> comptime evaluations) to the module that owns it, and report per-module totals
> + the context-free/context-sensitive split **measured, not asserted**.
> Read-only accounting.

## The finding that reshapes this card, before a line is written

**The per-declaration attribution already exists.** `Compilation.TimeReport`
(`src/Compilation.zig:866`) already carries, keyed by ZIR declaration
(`InternPool.TrackedInst.Index`):

| Field | What it holds |
|---|---|
| `decl_sema_info` | `{ ns, count }` per declaration — time **and instance count** |
| `decl_codegen_ns` | ns per declaration |
| `decl_link_ns` | ns per declaration |

And a declaration resolves to a module in two documented hops:
`TrackedInst.Index.resolveFile(ip)` → `FileIndex` (`src/InternPool.zig:186`) →
`Zcu.fileByIndex` → `File.mod` → `Package.Module.fully_qualified_name`.

So stage 2a is **a rollup of data the compiler already collects**, not new
instrumentation of `Zcu`. That is a correction to the plan's own wording, and it
is the difference between a large patch in a hot path and a small read-only one.
It also matches the round-2 ruling that C7 "already has its transport shipped":
`--time-report-json` is PROMOTED (`95cea4e2`, `abcd7bba`).

**Consequence for the doctrine:** no counter is added to any hot path, so the
accounting cannot change what it measures.

## The context-free / context-sensitive split, measured not asserted

`decl_sema_info.count` is documented as "the total across all instances of the
generic parent namespace, and (if this is a function) all generic instances of
this function". Therefore, per declaration:

- `count == 1` — analyzed once. A **context-free candidate**: nothing about it
  required re-analysis per use site.
- `count > 1` — analyzed `count` times. **Context-sensitive by observation**: the
  compiler actually re-analyzed it per instantiation.

This is an observation of what the compiler did, not a claim about what it could
have cached. `PLAN.md`'s law stands unchanged — "Anything not provably
context-free is treated as context-sensitive" — and this split is evidence for
stage 2c's key design, never a licence for it.

**Named limit, stated before the measurement is taken:** `count == 1` does NOT
prove a declaration is cacheable. It proves only that it was analyzed once in
*this* compilation. A declaration used from one site is indistinguishable here
from one that is genuinely context-free.

## Design — one new file, one hook

| Path | Change |
|---|---|
| `src/ModuleLedger.zig` | **new** — the rollup and its JSON emitter |
| `src/main.zig` | `--module-ledger <path>` parsed; one call beside `writeTimeReportJson` (`:3933`); refusal when its data source is absent |

Off by default. Absent the flag, nothing is computed and no output changes.

**Present-or-refuse-by-name:** the ledger's only data source is the time report.
`--module-ledger` without time-report data is a **named refusal**, not an empty
file and not a silent zero — doctrine principle 2, "an absent instrument reports
UNKNOWN, never zero".

|---|---|---|
| **C7-P1** | Rollup identity | Σ per-module `sema_ns` == Σ over all `decl_sema_info` entries; same for codegen and link. Nothing is lost or double-counted by the rollup. |
| **C7-P2** | Attribution is real | On a two-module fixture where module B does substantially more work than A, the ledger attributes more to B — and every declaration lands in exactly one module. |
| **C7-P3** | Split is measured | `context_free + context_sensitive == decls_total` per module, and a fixture with a generic instantiated at N>1 sites shows `count > 1` for that declaration. |
| **C7-P4** | Refusal fires | `--module-ledger` without its data source refuses **by name**; seen red. |
| **C7-P5** | Off by default | Without the flag, output is byte-identical to today. |
| **C7-P6** | On a rebuilt binary | All of the above on a stage3 built under the shared lock, never while the consumer event holds it. |

## Boundaries

Read-only accounting. It measures; it caches nothing, shares nothing, and
changes no artifact. It does not implement stage 2b, 2c or 2d, and a
context-free count is not a reuse decision.

**2,557 analyses beyond one per declaration.** That is the re-analysis stage 2c
would have to bank, measured rather than asserted.

The fixture is doing its job: `heavy` holds one generic instantiated at ten
types (4 context-sensitive of 5 declarations, 27 analyses) and one declaration
used once (`onlyOnce`, context-free). A split that could only ever land in one
column would prove nothing.

### What P4 found, and why it needed two halves

The first P4 went red on a defect that was not the one predicted: passing only
`--module-ledger` hit a pre-existing guard that refused by naming
`--time-report` — a flag the user never typed. Refusing by the wrong name is
worse than not refusing, because it sends the operator to the wrong place.
`--module-ledger` writes its own file and **is** a sink; the guard did not know
about it. Hence the control has two halves: the flag alone must WORK, and the
genuinely unsatisfiable case must refuse BY NAME. Either half alone would have
passed over the defect.
