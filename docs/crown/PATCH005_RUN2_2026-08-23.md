# patch/005 — the fixed tree, one build, one measurement pass (2026-08-23, second run)

Successor to `PATCH005_VERIFICATION_RUN_2026-08-23.md`, which ran the first batch and
**refused promotion** on two blockers. This file records what was changed in response,
the single build of the fixed tree, and the measurement pass over it.

**Method, and the reason for the shape.** The first batch fixed and re-measured in
alternation, which spent a ~40-minute compiler build per fix. This run is deliberately
three phases — *bake everything → build once → measure once* — so that N fixes cost one
build instead of N. The cost of that choice is honest and worth naming: **a defect in
any one bake is not isolated by the build**, so every source change carries a
`TYPECHECK_RC=0` receipt from the cheap oracle (`docs/crown/BUILDING.md` §5, ~45 s)
before it lands, and the measurement pass is what separates them afterward.

unpatched compiler fails the byte-repro row identically: 3/3 different digests at
default `-j`, 3/3 identical at `-j1`) and **V12-NEW as operative** (deterministic
semantic output on the 1,200-file AstGen fan-out, and `.text` section identity on the
std-pulling workload, both run differentially against the reference binary).

Its part 2 — a race detector — is where the honesty costs something. **ThreadSanitizer
remains unbuildable** here (`linux/scc.h`; see `BUILDING.md` §4), so a substitute is
named rather than the row being dropped: **Valgrind Helgrind, differentially**. Its
limitation was measured *before* adoption, not after — on the *unpatched* compiler a
trivial `build-obj -j2` yields `ERROR SUMMARY: 149968 errors from 343 contexts`, so the
absolute count fails its own negative control exactly as V12-OLD did. The instrument is
therefore the **difference** of normalised stack-context signatures, and its noise floor
was measured across all 6 pairings of 4 runs of the same unchanged binary: **0–7
filtered contexts**. That is the detection threshold, fixed before any comparison ran.

## The promotion rule — WRITTEN DOWN BEFORE THE MEASUREMENTS EXIST

Promotion is pre-authorised by the owner's standing order (*"the system zig ALWAYS
leverages the latest version we developed"*, where latest means **latest verified**), so
the decision falls to this lane. Recording the rule before any result arrives is the
only thing that stops it from being written to fit the numbers afterward. **This section
was committed before Phase 3 ran.**

**Promote only if ALL of these hold:**

1. **The build succeeds** and `zig version` → `0.16.0` from the new stage3.
2. **`main` compiles** after the cherry-pick.
3. **V-BR is fixed, measured:** a green `zig build` of a fixture emits **0**
   error-shaped bytes (`^error:`) and **0** `native failure` markers.
4. **V12-NEW parts (a) and (b) are clean** on the patched binary, with the reference
   binary run beside them.
5. **V1's four rows match the recomputed ceilings to the digit** — this is the
   end-to-end check that `ThreadPlan.index_bits` and `InternPool.getIndexMask` agree
   after the widening. A mismatch here means the compiler lies about its own capacity.
6. **No row is RED** under its operative criterion.
7. **No measured regression ships as a DEFAULT.** A slower arm may remain a selectable
   member; the default must be the measured-faster one.
8. **Because the `CaptureValue` widening touches the InternPool encoding — the deepest
   structure in the compiler — a functional test suite must run green.** Digest identity
   and timing do not exercise correctness of an encoding change. This condition is
   *stricter* than the standing order requires, and it is added deliberately: an
   encoding defect would not show up in any other row on this list.

**Do NOT promote if any row is RED.** UNKNOWN is not RED — but an UNKNOWN on a row that
would have tested the widening's correctness collapses condition 8 and therefore blocks.

**What is explicitly NOT a blocker,** so this is not decided by drift:
- Rows blocked by charter (V7a/V7b — a private workload this lane may not touch).
- Rows needing a sabotage rebuild (V3, V14, V-S2a, V-S2b, and V12's Helgrind positive
  control). Their harnesses are prepared under `partner_tools/vharness/sabotage/`; the
  builds are outside this run's one-build budget. They stay **UNKNOWN, not passing**.
- A timing delta inside the noise floor. "No regression visible" is the claim; anything
  more is not supported by a contended host.

The plan said one build. It took two, because build 1 was measured and found to ship a
**silent hang** (below). That is the cadence working, not failing: the second build exists
because a measurement refused the first, which is the entire point of measuring.

A trap worth inheriting: `stage3/bin/zig`'s ninja edge carries **only order-only
dependencies** (`|| zig-wasm2c zig1 zig2 zigcpp`) plus `restat = 1`. Order-only deps do
not dirty a target, so a plain `ninja` rebuilds `zig2` and leaves the OLD stage3 in
place — you would then measure a stale compiler and call it the new one. The build script
moves the output aside first (no `rm`; the fork's law) to force regeneration.

## Phase 3 — the measurement pass

Compiler under test: `046d6833…`. Reference: the promoted `60fad8a7…`. Mask `taskset -c
4-11` (8 logical / 6 physical), **CONTENDED** throughout. Full table:
`build-p005/vwork2/logs/final_vlist.md`; JSON sidecar under `build-vharness/runs/`.

**Roll-up: 20 GREEN · 4 RED · 9 UNKNOWN · 4 INCONCLUSIVE of 37 rows run** (registry 38).

### The blocker build 1 shipped, and the fix

`zig build-obj hello.zig` **with no flags at all** hung forever on a 2-physical /
4-logical mask — the ordinary shape of a 2-core CI container:

```
taskset -c 4,10,5,11  patched(build 1)  build-obj hello.zig  -> rc=124  (timeout 120)
taskset -c 4,10,5,11  reference         build-obj hello.zig  -> rc=0
```

It printed `intern partitions 2 (derived: physical…); alloc lanes 0` and then hung. It
named the cause of its own hang and did nothing about it, because **`alloc_lanes` was
computed, printed, and consulted by nothing** — it appeared only in `ThreadPlan.zig`.

`Id.allocate(K)` seeds the tid pool with `K−1` ids; the linker holds one for the whole
compilation; workers get `K−2`. At `K=2` that is zero and `Id.acquire` waits on `tid_cond`
with no refusal path and no timeout. Upstream cannot reach the state — one integer set
both quantities — so **the `(K, M_wide)` decoupling introduced it.** This is the silent-hang
class patch/001 exists to abolish and that patch/002 Finding 3 refused a one-line change
over.

Fixed in two halves (`3669ffc7`): derived plans floor the basis at 4 so the state is
**unreachable**, and an explicitly given `--intern-partitions` that would starve the lanes
is **refused by name** with the remedy. Enforcement lives in `setThreadLimit` — the one
site holding both quantities and the caller of `Id.allocate`.

Post-fix, all six V16 configurations (`V16` GREEN, 0 hangs of 6):

```
-j4 --intern-partitions=2   -> rc=1  "leaves 0 allocating lanes for 4 workers" (was rc=124)
no flags, 2 phys/4 logical  -> rc=0                                            (was rc=124)
no flags, 2 phys / 1 phys   -> rc=0                                            (unchanged)
-j1 --intern-partitions=2   -> rc=0   the serial member, NOT refused           (unchanged)
```

That last row is the over-fire guard: a guard that refused `-j1` would itself be a defect.

### Three harness defects found and fixed — none by relaxing a row

- **`V4` asked about the LINKER while running `-fno-emit-bin`**, which never links. It read
  `real_ns_link_flush = 0` as "the linker did not overlap" — a negative verdict drawn from
  a missing measurement. Now it emits a binary, returns **UNKNOWN** when no link phase is
  timed, and uses `cpu_ns_link` vs the flush tail as the positive signature.
- **`V1` arm 2 used `--intern-partitions=2`**, which the deadlock fix now correctly refuses,
  so the row went red *because the fix worked*. Moved to `=4`, which exercises the same
  `(given)` provenance path; the refusal is V16's job.
- **`V2-EXP` was pinned to an expectation the project had already retracted** and would have
  reported RED forever.

### V12 — the hard gate. Part 1 passes; part 2 is UNKNOWN, and the substitute was retracted.

`V12-P1-OLD` **GREEN**: the invalid criterion reproduces its own invalidity — the
*unpatched* reference fails byte-identity 5 of 5. `V12-P1A` **GREEN**: 1 distinct digest of
5 runs on the 1,200-file fan-out, identical to its own `-j1`. `V12-P1B` **GREEN**: `.text`
1 distinct of 5. An independent 20-run direct check: **1 distinct of 20 on both arms.**

**Part 2 remains UNKNOWN and the Helgrind substitute is RETRACTED by measurement.** Two
runs of one binary share ~140 stack contexts; two *different builds* share ~50 of ~450,
even after normalising away line numbers and `__anon_N` indices. Taken at face value the
comparison reads "276 new race contexts against a floor of 4" — **an artifact of
build-to-build symbolic drift, not a race result.** Only the same-binary control run beside
it prevented a spectacular false alarm. TSan is unbuildable here, Helgrind cannot compare
across builds, and no other race detector exists in this estate. **R12 stays READ-VERIFIED
ONLY — exactly the state the dossier said must not ship.**

| 2 | `main` compiles after the cherry-pick | **met** — `TYPECHECK_RC=0` |

| 4 | V12-NEW (a) and (b) clean, reference beside | **met** — P1A + P1B GREEN |
| 5 | V1's rows match the recomputed ceilings | **met** — GREEN 4/4, 31 bits derived |
| 6 | **no row is RED** | **NOT MET** — V8, V-S4b, H3 |
| 7 | no measured regression ships as a default | **met** — `insertion` and `keep` both default |
| 8 | **a functional test suite runs green** | **NOT MET** — H3 fails, though identically to the control |

Two conditions unmet, and **the hard gate V12 part 2 is UNKNOWN with its substitute
retracted**. The rule said: *do not promote if any row is RED.* It was written precisely so
this moment could not be argued away, and it is not being argued away now.

**`PROMOTED/zig` is untouched** and still resolves to `build-safe/stage3/bin/zig`.

### What the desk should weigh, stated without spin

The case *for* promoting anyway is real and should not be hidden: the two feature REDs are
comparison rows whose retraction has already been applied to the defaults (condition 7
exists precisely to allow a slower arm to remain a *selectable member*); H3 fails
**identically** on the pre-change tree, so it indicts nothing here; and the tree is
materially better than the promoted binary — it fixes a `main` that had not compiled for a
day, abolishes a silent hang, closes a diagnostic-channel break, doubles the index ceiling,
and removes a latent `Nav.Index` truncation.

The case *against* is that R12 — the one risk the dossier called a hard gate — is still
unmeasured, and this batch *reduced* confidence in the only substitute on offer. Promoting
would mean shipping the A1 lane split on a read-through, which is what the design document
forbade in advance.

**This lane refuses; the desk may overrule with the evidence above.** A single change would
settle it: a TSan-capable toolchain, or the budget for the prepared sabotage rebuild under
`partner_tools/vharness/sabotage/`.
