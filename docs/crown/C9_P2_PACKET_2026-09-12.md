## WIP facts verified against current bodies — and the two that had to be challenged

Every measured fact the dispatch carried was re-checked in this tree before
use. Two premises did not survive contact with the current bodies:

1. **The rung-4 WIP declared its graph fields REQUIRED; the rung-2 WIP's
   BLOCKER 2 finding proves that shape breaks rung 1.** `std.json` raises
   `error.MissingField` for a declared field a document omits, so
   required `index`/`root`/`root_src_path` would make today's flagless
   `--module-graph` run hard-fail on documents rung 1 has always accepted
   — an additive flag breaking the rung beneath it. All rung-2/4-only
   fields are `?T = null` here, and each rung refuses a field-less
   document **by name** at its own gate (`rung2FieldGap` /
   `resolveAsModule`), naming the array position, the field, the flag, and
   the re-emit remedy. The rung-4 WIP's shape is corrected, not repeated.

2. **The sketched lexical-shadowing control shape cannot reach rung 2.**
   "File-scope alias + function-local same-name alias" is an AstGen
   compile error in this tree: `detectLocalShadowing` walks to the
   enclosing namespace and fails any local that name-matches a container
   declaration (`lib/std/zig/AstGen.zig:12893`, reached from `localVarDecl`
   at `:3211`; container-in-container matching fails the same way at
   `:13163`). The file would die at AstGen and the decl check would never
   run. Control C9P2-03 instead exercises the counted-refusal contract
   with the reachable too-deep shapes — originally a function-local
   binding and an identifier chain; retained correction 3 retired the
   local-binding attribution, so the counted shape is the root identifier
   chain and the function-local binding is the ignored contrast — the
   RETIRED INTERMEDIATE state, superseded by retained correction 8: the
   function-local direct-const import is followed again, by exact
   ownership rather than spelling, so C9P2-03's CURRENT prediction counts
   it validated with its one call arity-matched (see the correction-8
   section). The
   fixture header records the corrections and the succession.

   The scope of that measurement was first overstated here, and senior
   review corrected it: it rules out a local shadowing a FILE-SCOPE name,
   nothing more. Two LOCALS in sibling function scopes lawfully reuse one
   spelling — one bound to `@import`, one to an unrelated value — and that
   collision is fully reachable through the shipped drivers; the first
   delivery of this packet misattributed the ordinary same-spelling access
   to the import alias (counted `alias_too_deep`, or `operand_unparsable`).

## Senior-review corrections on this packet's own delivery

nothing outside the ownership list was touched. Every correction remains

1. **BLOCKER — the claimed single path-resolution seam was not real.**
   `classifyMemberRef` resolved rung 2's FILE-IMPORT member targets with a
   bare `std.fs.path.join`, one call site away from the `resolveImportPath`
   seam the packet claimed, so rung 1 and rung 2 did NOT locate a file
   target the same way, and the absolute-operand failure was reintroduced
   (an absolute operand was resolved into the checked file's directory).
   Fixed: the file-import branch now goes through `resolveImportPath`,
   making the one-seam claim true for all three consumers. The
   discriminating control IS expressible without inventing invalid Zig
   input — a string-literal absolute operand parses AND passes AstGen
   (import-path resolution is Sema's job, not AstGen's), so the shipped
   drivers, which gate the graph/decl checks on a successful AstGen,
   proceed to run them on it — but no STATIC fixture can spell a
   discriminating absolute path portably (a path inside the repository
   varies by checkout; a path outside it varies by machine). Control
   C9P2-32 therefore renders its checked file at run time from
   `ABS_OPERAND_TEMPLATE`, substituting this checkout's absolute
   `util.zig` path; preflight verifies the template's statics, and the
   default manifest mode writes nothing. The absolute-operand outcome
   itself remains a PREDICTION until the rebuilt control is actually
   run.

2. **MAJOR — local import aliases were collected into file-global name

### Owner and API

`lib/std/zig/AstGen.zig` is the one semantic binding owner. Its private
`Scope` chain (`LocalVal`, `LocalPtr`, `Namespace`) is walked by `localVarRef`
for every non-primitive identifier (`AstGen.zig:8132-8400`); parameters and
all capture forms enter those same `LocalVal` scopes. The scope objects are
temporary and may point into AstGen's arena, so they must not escape.

The exported public observation is scalar-only and opt-in:

```zig
pub const IdentifierBindingCategory = enum {
    function_parameter,
    local_constant,
    local_variable,
    capture,
    switch_tag_capture,
};

pub const IdentifierBinding = union(enum) {
    declaration: Ast.Node.Index,   // the use resolved to a namespace declaration
    local: struct {
        declaration_token: Ast.TokenIndex,   // token_src of the resolved LocalVal/LocalPtr
        category: IdentifierBindingCategory, // mapped 1:1 from Scope.IdCat
    },
    unavailable,                   // conflicting repeats; also the state left by
                                   // the clear-on-diagnostics branch
};

pub const IdentifierBindings = struct {
    // Identifier-use AST node -> the binding localVarRef selected, recorded
    // at the moment of resolution. The map type preserves insertion order,
    // but that is not a contract: AstGen does not promise that lowering
    // order equals lexical source order, and iteration is not in the
    // supported consumer contract (get(node) + deinit(gpa)); no order or
    // completeness is guaranteed.
    pub fn get(self: *const IdentifierBindings, node: Ast.Node.Index) ?IdentifierBinding;
    pub fn deinit(self: *IdentifierBindings, gpa: Allocator) void;
    // PRIVATE (correction 9): fn record(...) -- the owner's single recording
    // path, shared by localVarRef's production call and the semantic unit
    // test; mutable map access is deliberately not consumer API.
};

pub const GeneratedWithIdentifierBindings = struct {
    zir: Zir,
    bindings: IdentifierBindings,
};

pub fn generate(gpa: Allocator, tree: Ast) Allocator.Error!Zir;   // unchanged
pub fn generateWithIdentifierBindings(
    gpa: Allocator,
    tree: Ast,
) Allocator.Error!GeneratedWithIdentifierBindings;
```

`generate` remains the existing signature and calls one private lowering body
(`generateInner`) with a null observer. The new entry point stages an empty
sidecar, installs `errdefer bindings.deinit(gpa)`, and calls the same body with
its address. `localVarRef`, at the exact successful lookup branches it already
owns, records either the selected `LocalVal`/`LocalPtr`'s `token_src` plus
mapped `IdCat`, or the exact `found_already` declaration node after namespace
ambiguity has been resolved. It records before a namespace reference is
transformed by `tunnelThroughClosure`, so a closure instruction cannot erase
the binding decision. No AST or ZIR pass reconstructs scope. Primitive and
builtin early returns do not manufacture a fact. A repeated AST use node that
arrives with a conflicting fact collapses to `unavailable` (compared with
`std.meta.eql`), never last-writer-wins.

The sidecar owns only its hash storage, and the storage is owned by the CALLER:
`generateWithIdentifierBindings` stages it and returns it by value; the AstGen
struct's `identifier_bindings` field is a nullable observer address, not an
owned pointer, and AstGen's `deinit` does not free it. Its records are integer
AST node/token indices and an enum: no `Scope` pointer, ZIR instruction
reference, string-table index, or source slice survives. It is valid only
alongside the exact `Ast` passed to the generating call; `deinit(gpa)` releases
it independently of ZIR.

### Transaction, errors, and disabled-path cost

- The new entry point owns a local empty sidecar and installs `errdefer
  bindings.deinit(gpa)` before lowering. Any OOM from the existing lowering or
  the new map insertion therefore releases all sidecar storage. The existing
  AstGen/ZIR defers remain unchanged.
- A returned ZIR carrying ANY diagnostic publishes an EMPTY sidecar. Retained
  correction 9 widened the trigger from `fatal` parse/AnalysisFail lowering to
  the diagnostic content itself: `structDeclInner` may return successfully
  while `astgen.compile_errors` already holds diagnostics, so the clear branch
  is `fatal OR a non-empty compile_errors list` -- EVERY diagnostic lowering,
  not only the fatal shapes. Partial binding observations made before the
  failure are cleared before return and are never consumable as a valid scope
  census; a clean lowering keeps every fact. Both checker drivers already
  refuse to run rung 2 on such a ZIR.
- The single-file and batch checker paths install `defer
  generated.bindings.deinit(the_same_allocator)` immediately after the opt-in
  call, so render failures and all early returns are covered. Their existing
  ZIR/error-bundle ownership remains untouched.
- Ordinary compilation consumers remain on `generate`: `Builtin.zig`,
  `Zcu/PerThread.zig`, `fmt.zig`, `lib/std/zig.zig`, `compiler/reduce.zig`,
  `tools/gen_spirv_spec.zig`, and the non-C9 `main.zig` call sites do not request
  or retain facts. With the null observer there are zero sidecar allocations
  and zero retained bytes. The exact added disabled-path runtime cost is one
  predictable null check at each successfully resolved non-primitive
  identifier; no source/tree/ZIR traversal is added. The authored source does
  not replace that statement with a stronger zero-instruction claim: measurement
  may prove specialization removed the branch, but no such measurement has been
  made, and none is claimed here.
- Batch requests facts only when `check_decls == true`; ordinary batch
  `ast-check`, graph-only checking, formatting, compilation and reduction stay
  on `generate`. Single-file `cmdAstCheck` likewise opts in only for
  `--check-decls`; the other `main.zig` AstGen consumers stay unchanged.
- Allocation honesty (retained correction 9): the flagless and graph-only
  paths never REQUEST the sidecar at all -- they stay on `generate` with zero
  sidecar allocations. A `--check-decls` run whose lowering produces
  diagnostics is DIFFERENT: the sidecar was requested before lowering and may
  have allocated facts on the way to the failure, which the widening above
  then clears before publication -- requested-then-cleared, never
  zero-allocation. No claim is made that a diagnostic lowering allocated

### Checker composition and honest support boundary

`checkAgainstGraph` and `checkDeclExistence` receive `*const
AstGen.IdentifierBindings`; batch threads the same per-file object directly.
The existing structural walk may map a local declaration's unique name token
to its `fullVarDecl` solely to inspect whether that exact owner is a `const`
whose initializer is a direct `@import` call. That token-to-node join is not a
scope lookup: AstGen has already selected the binding.

At a field access whose immediate LHS is an identifier:

| AstGen fact | Rung-2 treatment |
|---|---|
| exact declaration node naming an existing root direct-const import | preserve current follow/name/arity behavior, now keyed by node rather than file-wide spelling |
| exact local `local_constant` token whose declaration is directly initialized by a parseable `@import` | newly supported; follow through the existing `resolveImportPath`, target cache, public-decl and arity owners |
