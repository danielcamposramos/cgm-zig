cgm-zig / What changes

What changes

cgm-zig is a patch set on Zig 0.16.0. Every new compiler behaviour sits behind a new flag, so a stock invocation behaves like stock Zig.

The rows below are drawn from the repository’s commit messages and verification records. Where the record holds no measurement of a change’s effect, the row says not yet measured and does not claim one. The full table, with every file and commit, is in the README.

“Ships off” means the change is in the build but only runs when you ask for it, because its own measurement came out slower.

How it was checked

The repository keeps a verification harness of 38 rows that register themselves. After three defects in the harness were fixed without relaxing any row, its final table reads 22 green, 2 red, 9 unknown and 4 inconclusive. The two reds are the two features that ship off. The harness found the hang and the noisy report line above; neither was a row someone had queued. Source: (f) in the README.

What is not claimed

  • No speed-up against any other configuration. The two compile-time figures above are wall-clock readings.
  • The clean-machine cost acceptance for the newer candidate is unfulfilled, and the repository says no retroactive performance pass is given.
  • Neither build is a portable Linux package: both need the system’s LLVM and Clang 21.1 libraries.
  • No change to the language, and none to the standard library beyond three additions (std.Thread.Topology, Io.Threaded.concurrent_reserve and std.Build.Graph.child_jobs) and one enum member, each with a stock-preserving default.

Which Zig version

0.16.0 is the base and the patch target. Version 0.17 enters only after upstream promotes it to stable; the 0.17 development line failed on the motivating workload from language changes alone, before reaching the crash. Source: README, “What the fork does not change”.
